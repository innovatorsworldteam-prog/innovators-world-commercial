## How to use this document

### Review matrix columns (15)

| # | Column | Meaning |
|---|---|---|
| 1 | Review # | Sequential 1–106 across the six batches |
| 2 | Proposed name | `proposed_name` from the inventory |
| 3 | Proposed slug | `proposed_slug` (identity key; do NOT treat as a canonical ID) |
| 4 | Cluster | 01–14 cluster key |
| 5 | Proposed status | `current` · `specialist` · `emerging` · `future` (evidence-assigned) |
| 6 | Evidence status | evidence tier + classification label |
| 7 | Provenance (short) | condensed `provenance` / `basis` family |
| 8 | Current proposed resolution (research) | carry-over `decision` / `resolution` from the candidate phase |
| 9 | Potential duplicate/overlap | the overlap the reviewer is asked to arbitrate |
| 10 | Rel. to seed | `seed` · `alias-of-seed` · `related` · `—` |
| 11 | Editorial issue | the specific question for the human reviewer |
| 12 | Recommended review decision (AI) | **OpenCode's recommendation** — do not treat as binding |
| 13 | Reason for recommendation (AI) | the reasoning behind column 12 |
| 14 | Human decision | **leave blank** — for the reviewer (APPROVE/MERGE/ALIAS/MOVE/REJECT/DEFER) |
| 15 | Human notes | **leave blank** — for the reviewer |

### Decision vocabulary

| Decision | Meaning |
|---|---|
| **APPROVE** | Include as a World 01 canonical career under the proposed identity |
| **MERGE** | Fold the candidate into another canonical identity (as specialisation vocabulary), do not create a record |
| **ALIAS** | Make the candidate an SEO/display alias of another canonical identity, no separate record |
| **MOVE** | Candidate is real but belongs in another World (destination recorded); record a hand-off intent |
| **REJECT** | Excluded from the canonical universe (absorbed, transitional, grade, or failing the distinct-career test) |
| **DEFER** | Set aside for a later editorial round; re-review trigger recorded |

### Suggested review workflow

1. Work batch by batch (Batch 1 → Batch 6), 15–20 minutes each, filling columns 14/15 in the Decision Register at the end.
2. Record every human decision in **Section R (Decision Register)** — it is the working record; the batch tables are the reference.
3. Decide identity-anchoring cases first (Section G gives the recommended order), because MERGE/ALIAS decisions depend on what the anchor careers are.
4. When done, return the completed document (or a decisions summary) to begin canonical import planning. **No import happens from this document.**
